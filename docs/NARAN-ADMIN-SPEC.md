# Өөрийн эзэмшилтэй, мэргэжлийн түвшний back-office

Энэхүү баримт нь «Наран Америк бараа» дэлгүүрийн **админ / back-office** хэсгийг
дэлгүүр ажиллуулах багийнхны өдөр тутмын ажилд бүрэн нийцсэн, мэргэжлийн түвшинд
хөгжүүлэх бизнесийн шаардлага, техникийн шийдэл, үе шаттай төлөвлөгөө, зардлыг
тодорхойлно.

**Гол зарчим — зардал багатай, чанартай:** бид шинэ админ системийг эхнээс нь
бүтээхгүй. Medusa v2-ийн **нээлттэй эх (MIT), лицензийн төлбөргүй Admin**-ыг суурь
болгож, дээр нь Нараны ажлын урсгалд тохирсон **зорилтот өргөтгөлүүд** (custom
хуудас, widget, тайлан, эрхийн хяналт) нэмнэ. Ингэснээр захиалга/бараа/харилцагчийн
үндсэн CRUD-ийг дахин бичихгүй (Medusa бэлэн өгдөг), зөвхөн жинхэнэ үнэ цэнэ
нэмэх хэсэгт хөрөнгө оруулна.

| Үзүүлэлт | Шийдэл |
| --- | --- |
| Суурь | **Medusa v2 Admin · React · open-source (MIT)** |
| Өргөтгөл | **UI routes, widgets (injection zones), custom API, workflows** |
| Эрхийн хяналт | **@medusajs/rbac модуль + policy enforcement** |
| Нэмэлт хостинг | **₮0 — одоо байгаа Medusa процесс дээр ажиллана** |
| Хугацаа | **~6 үе шат · ~48 хүн-өдөр** (нэг хөгжүүлэгч) |

## 00. Гүйцэтгэх удирдлагын хураангуй

Одоогийн байдлаар Нараны админ нь **Medusa v2 Admin** (бараа, захиалга, харилцагч,
урамшуулал, агуулах, тохиргоо) дээр ажиллаж, түүн дээр **гурван захиалгат хуудас**
(Каталог — bulk import/export + stats, Аналитик — борлуулалтын самбар, Буцаалт —
зөвшөөрөх queue) нэмэгдсэн. Энэ нь суурь хэрэгцээг хангадаг ч, олон ажилтантай,
олон мянган бараатай **мэргэжлийн үйл ажиллагаанд** дараах зүйлс дутуу байна:
эрхийн ялгаатай хандалт (RBAC), захиалга биелүүлэх бүрэн урсгал, харилцагчийн
сегмент (CRM), контент удирдлага (нүүр хуудас/баннер), нарийвчилсан тайлан,
мэдэгдэл, аудит лог.

Энэ баримт нь эдгээрийг **Medusa-ийн өргөтгөх механизмаар** (шинэ админ апп биш)
нэмэх төлөвлөгөөг тодорхойлно. Үр дүнд нь дэлгүүрийн баг терминал ашиглахгүйгээр
өдөр тутмын бүх ажлыг (бараа нэмэх, захиалга бэлтгэх, буцаалт, нөөц, урамшуулал,
тайлан) нэг самбараас, эрхийн хяналттайгаар гүйцэтгэнэ.

#### Юуг шийдэж байна
Олон ажилтан бүр өөрийн үүрэгт тохирсон эрхтэйгээр, олон мянган барааг үр ашигтай
удирдаж, захиалгыг хурдан биелүүлж, борлуулалтаа хэмждэг мэргэжлийн back-office.

#### Яагаад Medusa Admin дээр өргөтгөх вэ
Шинэ админ апп бүтээх нь захиалга/бараа/харилцагчийн CRUD, auth, UI-г дахин бичих
том зардал. Medusa Admin эдгээрийг **үнэгүй, туршигдсан** байдлаар өгдөг ба
**албан ёсны өргөтгөх API** (UI routes, widgets, settings, custom endpoints)-тэй.
Иймд бид зөвхөн Нарны онцлог ажлын урсгалд хөрөнгө оруулж, зардлыг эрс бууруулна.

#### Хэдэн төгрөг шаардлагатай вэ
**Нэмэлт дэд бүтцийн зардал ₮0** — админ өргөтгөл нь одоо байгаа Medusa процесс
дотор ажиллана (тусдаа сервер/хостинг шаардахгүй). Зөвхөн **хөгжүүлэлтийн ажил**
(~48 хүн-өдөр, 10-р бүлэг).

## 03. Хамрах хүрээ

### Гэрээнд багтах (In scope)
- Эрхийн хяналт (RBAC): үүрэг, зөвшөөрөл, ажилтан урих
- Захиалга биелүүлэх ажлын урсгал: fulfillment queue, багц биелүүлэлт, түүвэрлэх жагсаалт (picking list) хэвлэх
- Каталог: одоо байгаа bulk импорт/экспорт дээр — багц засвар (үнэ/төлөв/ангилал), медиа удирдлага
- Нөөц: бага нөөцийн мэдэгдэл (одоо байгаа тайлан дээр), нийлүүлэлтийн тэмдэглэл (нэмэлт)
- Харилцагч (CRM): сегмент/бүлэг, тэмдэглэл, LTV, экспорт
- Маркетинг: урамшууллын нэгдсэн харагдац, орхисон сагсны мэдээлэл
- Контент (CMS): нүүр хуудасны баннер/hero/ангиллын контентыг админаас удирдах
- Тайлан: борлуулалт, НӨАТ (e-Barimt), нөөц, экспорт (CSV/Excel)
- Мэдэгдэл: бага нөөц, шинэ захиалга, буцаалтын хүсэлт
- Аудит лог: чухал үйлдлийг хэн, хэзээ хийсэн
- Админыг монгол хэл рүү орчуулах (Medusa admin i18n)

### Багтахгүй (Out of scope, дараагийн шат)
- Гар утасны нативе админ апп
- Гүнзгий ERP/нягтлан бодох бүртгэлийн интеграц (зөвхөн экспорт)
- Автомат нийлүүлэлтийн захиалга (PO) — зөвхөн гар тэмдэглэл
- BI/өгөгдлийн агуулах (data warehouse)

## 07. Техникийн шийдэл ба өргөтгөх механизм

Medusa v2 Admin-ыг **дотор нь** өргөтгөнө (тусдаа апп биш). Ашиглах механизмууд:

| Механизм | Юунд | Жишээ (одоо байгаа) |
| --- | --- | --- |
| **UI Routes** (`defineRouteConfig`) | Шинэ бүтэн хуудас, sidebar цэс | Каталог, Аналитик, Буцаалт |
| **Widgets** (`defineWidgetConfig`, injection zones) | Одоо байгаа хуудсанд блок нэмэх | Захиалгын дэлгэрэнгүйд e-Barimt/аудит блок |
| **Settings pages** | Тохиргооны хэсэгт | RBAC үүрэг удирдах |
| **Custom Admin API** (`src/api/admin/*`) | Backend логик | `/admin/catalog/*`, `/admin/returns/*` |
| **Workflows / Subscribers** | Автомат үйлдэл, мэдэгдэл | order.placed → e-Barimt, shipped имэйл |
| **@medusajs/rbac** | Үүрэг/policy загвар | Enforcement middleware хийнэ |

**RBAC хэрэгжүүлэлт:** `@medusajs/rbac` модуль нь role/policy/inheritance өгөгдлийн
загвартай. Дараах ажил хэрэгтэй: (1) модулийг тохируулж migration ажиллуулах,
(2) admin API-д policy шалгах **middleware**, (3) үүрэг/эрх удирдах **settings хуудас**,
(4) ажилтан урих үед үүрэг оноох. Энэ нь дунд зэргийн ажил (эхнээс RBAC бичихгүй).

**Гүйцэтгэл (10k+):** жагсаалтууд server-side pagination + Medusa index/шүүлт
ашиглана (одоогийн Каталог/Аналитик хуудас ингэж хийгдсэн — count query, багцалсан).
